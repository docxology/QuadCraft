# Cartesian chunk keys and local quadray block storage

[Development index](README.md) · [Native API](api_reference.md) · [Architecture](architecture.md)

## Coordinate spaces

[`World.h`](../../src/core/world/World.h) uses `(chunkX, chunkY, chunkZ)` Cartesian grid indices. With `TetraChunk::CHUNK_SIZE = 16`, chunk `(cx,cy,cz)` covers `[16cx,16(cx+1))` on x and corresponding y/z intervals. `worldToChunkCoords()` uses `floor`, including negative coordinates: Cartesian x = -20 belongs to chunk x = -2.

`World::getBlock/setBlock` accept a **world quadray**, embed it in Cartesian space, select the chunk, then call `worldToChunkSpace()`. That method subtracts the Cartesian chunk origin and converts back to a **local quadray**. Do not pass world positions directly to `TetraChunk::setBlock`.

[`ChunkMesher.cpp`](../../src/render/mesh/ChunkMesher.cpp) performs the reverse offset when emitting vertices. Its output is world-space geometry drawn with an identity model matrix. Chunks are Cartesian cubes containing tetrahedral elements, not tetrahedron-shaped chunk regions.

## Creation is not generation

| Operation | Behavior |
|---|---|
| `World::getChunk(cx,cy,cz)` | Returns existing storage or inserts an empty `TetraChunk` |
| `World::getOrCreateChunk(cx,cy,cz)` | Returns existing storage unchanged; a newly inserted chunk calls `generate()` |
| `World::getBlock(q)` | Does not create chunks; absent chunk/element reads as air |
| `World::setBlock(q,id)` | Gets/creates empty storage, then changes the local element |
| `TetraChunk::generate()` | Clears existing elements, calls the terrain generator, marks generated/dirty |

A chunk created by a block write is not automatically terrain-generated by a later `getOrCreateChunk` call. Calling `generate()` explicitly destroys its edits. There is no persistence/merge layer to reconcile those operations.

## Storage and numeric limits

[`TetraChunk.h`](../../src/core/world/TetraChunk.h) stores non-air `TetrahedralElement` values in an `unordered_map`; setting air erases an element. The hash normalizes the quadray and hashes exact float values, while equality compares normalized coefficients with an epsilon. Approximate equality and exact hashing are not a robust general approximate-key design; do not promise that arbitrarily nearby floating samples identify the same block. There is no integer cell quantizer in the world API.

[`TerrainGenerator.h`](../../src/core/world/TerrainGenerator.h) samples an 8-by-8-by-8 Cartesian lattice per chunk and considers five tetrahedron centers per sample cube. Its multioctave sine field chooses material by height/cave/ore conditions. The stored element reconstructs its own tetrahedron geometry; this is not a verified conforming five-tetrahedra volumetric mesh or an isosurface extractor.

## Dirty meshes and boundaries

`setBlock` marks its chunk dirty. `getDirtyChunks()` returns generated dirty chunks; [`Game::updateChunkMeshes`](../../src/game/Game.cpp) builds up to its per-frame budget, stores meshes by key, and clears the dirty flag. Camera movement also marks all chunks dirty, so the implementation does not rebuild only after block edits.

`TetraChunk::getNeighbors()` reflects the center toward each face and converts the result to a quadray. Face visibility uses `World::getBlock` at those points, allowing queries across chunk boundaries. `updateNeighborChunks(World&)` marks six Cartesian neighbor chunks dirty, but `World::setBlock` does not call it automatically. These helpers do not establish watertight boundary meshing or complete neighbor invalidation.

## Loading and unloading

`generateChunksAround` visits integer offsets inside an approximate sphere and increases radius with distance from the origin. `updateChunks` requests the configured generation radius and removes at most five distant non-visible chunks per call, with a height-dependent distance threshold. Generation and meshing are synchronous. No chunk job scheduler, serialization/compression store, lighting engine or multi-resolution LOD system exists.

[`tests/world_chunk_test.cpp`](../../tests/world_chunk_test.cpp) covers Cartesian generation keys, radius selection, positive/negative block access, chunk centers and local/world conversions. It is not a rendering, performance or exhaustive topology test. [Verification commands](testing_guide.md) include the graphics-free target.

## Design considerations, not implemented APIs

A future streaming system would need explicit ownership of generation versus edits, canonical numeric cell keys, neighbor invalidation, mesh eviction and durable storage before asynchronous loading could be safe. These are design constraints, not available `ChunkManager`, serializer or event classes.
