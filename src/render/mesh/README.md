# Native Vertex buffers and heuristic chunk meshing

[Mesh.h](Mesh.h) defines `Vertex { Vector3 position, normal, color; float texCoordU, texCoordV; }`. `Mesh::create(const std::vector<Vertex>&, const std::vector<unsigned int>&)` uploads data; `render() const` and `render(int) const` draw it. `isInitialized`, vertex/index counts and the destructor manage/query GPU state. There are no public `upload/bind/draw/clear` methods.

[ChunkMesher.cpp](ChunkMesher.cpp) creates a mesh from non-air elements, offsets local vertices by the Cartesian chunk origin, applies a small inward inset, assigns per-face vertex colors and emits three separate vertices per rendered triangle. It does not share vertices or batch by texture. Texture coordinates are currently unused zeros.

Face visibility queries the world through reflected-neighbor positions and air/transparent flags. When a face's cross product points inward, the mesher swaps its second/third emitted vertices and negates the normal, producing outward CCW winding and aligned lighting normals. This corrects culling order, not topology: element vertex offsets are nonregular and face indexing/reflection does not prove a consistent tessellation. The element processing guard can truncate large chunks. Game budgets dirty regeneration; camera-only motion does not remesh world-space geometry, and edits dirty only their own chunk, so neighbor boundary faces can remain stale. There is no demonstrated sub-10ms guarantee.

Mesh GPU owners must be destroyed with their GL context live/current. `Game` evicts unloaded meshes during update and clears mesh/shader owners before window teardown. [Real-GL consumers](../../../docs/development/testing_guide.md#real-opengl-rendering-and-framebuffer-artifacts) check uploaded geometry, framebuffer and ownership behavior; their existence is not a passing runtime receipt.
